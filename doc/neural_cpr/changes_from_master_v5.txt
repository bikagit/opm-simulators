doc/neural_cpr/ FILES — differences from v3
--------------------------------------------

doc/neural_cpr/cpr_policy.model  ← CHANGED vs v3
  v3 value: copy of cpr_policy_v3_2decks.model (1326 samples, 45.5% val_acc)
  v5 value: copy of cpr_policy_v5_6decks.model (2762 samples, 37.0% val_acc)
  Format and architecture are identical (14→32→24 ReLU Kerasify binary).
  Only the trained weight values differ.

doc/neural_cpr/collect_sweep_labels.py  ← CHANGED vs original (bug fix)
  Change: join key changed from (episode, newton_iter) to
          (deck, episode, newton_iter).
  Reason: different reservoir decks share the same episode/newton numbering.
    Without the deck prefix, Newton steps from SPE9 and Norne with the same
    episode=0, iter=0 would be merged into a single sample, corrupting the
    label assignment.
  Impact: with 6 decks, the bug would have silently dropped or corrupted
    a significant fraction of samples. The fix is present in both the v5
    data pipeline and in the v3 branch (applied retroactively), but only
    matters for multi-deck sweeps.
  Also added: deck column in output CSV; deck identifier derived from
    filename stem by stripping trailing _NN config label.

doc/neural_cpr/cpr_policy_v3_2decks.model  (present in both branches)
  Reference checkpoint for the v3 model. Unchanged.

doc/neural_cpr/cpr_policy_v5_6decks.model  (present in both branches)
  Active model for this branch. Same file as cpr_policy.model in v5.
  Trained: 6 decks, 2762 samples, val_acc = 37%.

doc/neural_cpr/cpr_policy_v6_tanh24.model  (present in both branches)
  Experimental checkpoint: 14→24→24 tanh architecture.
  Not active in any production branch. Kept for reference.

doc/neural_cpr/run_sweep.py  (unchanged from v3)
  Same tool as in v3. Covers the full 3×2×2×2 = 24 config space.
  Used for sweep4 (Drogon, 0_BASE_MODEL2, SPE3CASE1, SPE9_CP).

doc/neural_cpr/train_cpr_policy.py  (extended vs v3)
  Changes vs. the script used for v3:
    - --hidden argument: configurable hidden layer width (default 32)
    - --activation argument: relu / tanh / softplus (default relu)
    - --class-weights flag: inverse-frequency weighting with --weight-cap
    - Default export format changed from kerasify to binary (no opm.ml
      Python package required)
    - normalise() and all activation forward/backward functions reviewed
      for consistency with CprPolicyFeatures::toArray()
  Note: the diag_dominance normalisation is clamp(val/4.0) in v5, matching
    v3 and the current CprPolicyFeatures.hpp. An experimental log10 scale
    was tried (v6 branch) but reverted for model compatibility.
